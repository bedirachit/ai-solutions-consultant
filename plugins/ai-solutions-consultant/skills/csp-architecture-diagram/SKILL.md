# CSP-specific architecture diagrams (draw.io)

## Non-negotiables

1. **Official icons for the named provider.** Azure → `azure2` library;
   AWS → `aws4` library (current architecture icons, not `aws3`/`aws3d`);
   GCP → `gcp2` library (or current Google Cloud icons from search);
   on-prem → generic network/data-center shapes. Never draw cloud services as
   plain boxes when an official icon exists. Get exact style strings from the
   draw.io connector's `search_shapes` — do not guess image paths.
2. **Always deliver an "Open in draw.io" link** generated by
   `scripts/drawio_link.py`, plus the `.drawio` file. Do not deliver the file alone.
3. **Every edge is labelled** with what flows (protocol / data / direction)
   when it is not obvious.
4. **One diagram, one question.** Context, logical, physical/deployment, flow
   (current vs proposed) and security/network views are separate diagrams.

## Procedure

1. **Spec first.** From the architecture write-up, list: components (name +
   service), groups (cloud → region → VNet/VPC → subnet; on-prem → DMZ /
   core zone; SaaS vendor zone), edges (source → target, label, sync/async),
   and the legend items. Confirm the view type.
2. **Load the drawing rules.** Call the draw.io connector's
   `get_drawio_reference` (format `xml`) once per conversation.
3. **Find icons.** For each component call `search_shapes` with the provider
   prefix and service name ("azure api management", "aws4 bedrock",
   "gcp vertex ai", "firewall", "server"). Pick the result from the official
   library per `references/<provider>.md`. Record the style string.
4. **Lay out** per `references/layout-conventions.md`: left-to-right flow from
   users/channels to systems of record, provider group containers, consistent
   icon size (48–64 px), label under icon, 40 px grid spacing.
5. **Render** with `create_diagram` (XML). Use `routing: "libavoid"` for
   hand-placed layouts. Keep to roughly 30–40 shapes per diagram; split if more.
6. **Produce the file and link.** Save the same XML to a file and run:
   `python3 ${CLAUDE_PLUGIN_ROOT}/skills/csp-architecture-diagram/scripts/drawio_link.py <file.xml> --out <name>.drawio`
   Share the `DRAWIO_LINK` as a clickable markdown link ("Open in draw.io")
   and deliver the `.drawio` file. If the link is over ~8,000 characters, say
   that the file is the reliable path (draw.io → File → Open).
7. **Exports for documents and decks.** When the user needs an image (e.g. their
   wiki blocks draw.io embeds), export PNG/SVG from draw.io or render the XML
   with draw.io desktop/CLI if available; otherwise tell the user to use
   draw.io → File → Export as → PNG.
8. **Partner review gate** before presenting as final.

## If the draw.io connector is not connected

Write the XML using the style patterns in the provider reference files, run the
link script, deliver link + file, and tell the user that connecting the draw.io
connector enables inline previews and icon search.

## References

- `references/aws.md` — AWS aws4 icons and group containers.
- `references/gcp.md` — Google Cloud icons and grouping.
- `references/onprem-hybrid.md` — on-prem, network, telephony and SaaS-vendor shapes.
- `references/layout-conventions.md` — layout grid, colors, legend, view types, quality checklist.
